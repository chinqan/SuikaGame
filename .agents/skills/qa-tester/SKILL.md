# 物理落下益智遊戲 — QA 測試工程師

**職能**：設計並執行全面的測試計劃，涵蓋功能驗證、效能基準、跨平台測試、邊界條件。

---

## When to Use

- 設定新功能的測試計劃與驗收標準
- 定義效能基準指標
- 建立跨平台/跨瀏覽器測試矩陣
- 測試物理引擎相關的邊界條件
- 回歸測試（修改後確認未破壞現有功能）
- 驗收 GDD 中定義的規格是否正確實作

---

## 品質標準

### GDD 一致性驗證

- **GDD 更新後，必須同步更新對應的測試項目**
- **數值型規格必須有可量測的驗收標準** — 不能只寫「正常運作」，要寫「COMBO 窗口 = 1200ms ± 50ms」
- **Texture 規格可驗證** — 從 GDD 的繪製規格能還原出相同的視覺結果

### 測試項的可執行性

- 每個測試項必須有**明確的操作步驟 + 預期結果**
- 效能指標必須有**量測工具和方法**
- 邊界條件必須有**觸發方式**

## 核心玩法測試撰寫指南

### 測試項模板

```markdown
## [功能名稱]

- [ ] [操作步驟] → [預期結果]
- [ ] [邊界條件] → [預期行為]
- [ ] [異常情況] → [預期容錯]
```

### 必須涵蓋的玩法測試

```markdown
## 合成機制

- [ ] 兩個同等級形狀碰撞 → 合成為下一等級
- [ ] 最高等級碰撞 → 不合成，正常碰撞
- [ ] 合成位置 → 在兩形狀碰撞中點生成
- [ ] 連鎖合成 → 新形狀可立即觸發下一次合成
- [ ] 跨等級碰撞 → 不觸發合成

## 投放機制

- [ ] 投放後有冷卻期
- [ ] 投放位置受邊界限制
- [ ] 冷卻中隱藏瞄準導線

## COMBO 系統

- [ ] 窗口時間內連續合成 → COMBO 計數遞增
- [ ] 超過窗口時間 → COMBO 重置
- [ ] COMBO 文字正確顯示

## Game Over

- [ ] 形狀靜止後超過判定線 → 觸發結束
- [ ] 合成瞬間不判定（防止誤判）
- [ ] 下落中形狀不判定
```

## 難度系統測試撰寫指南

測試難度時，必須驗證**每個難度軸的獨立正確性**：

```markdown
- [ ] 各難度的形狀數量是否正確（對應 shapesSlice 配置）
- [ ] 各難度的投放等級上限是否正確（對應 maxDropLevel 配置）
- [ ] 切換難度 → 遊戲狀態完全重置
- [ ] 切換難度 → Texture 快取重建（舊形狀不殘留）
- [ ] 排行榜按難度正確分組
```

> **關鍵原則**：難度配置必須與程式碼中的配置結構（如 `DIFFICULTY_MAP`）精確對應。

## 效能基準撰寫指南

### 指標模板

```markdown
| 指標 | 目標（桌機） | 目標（行動裝置） | 測量方式 |
|------|------------|---------------|---------| 
| FPS | ≥ 60fps | ≥ 55fps | [工具] |
| 記憶體 | < [N]MB | < [M]MB | DevTools Memory |
| 首次載入 | < [X]s | < [Y]s | Performance API |
| Texture 快取 | < [N]MB | < [M]MB | 自訂計數 |
| 同時粒子數 | < [N] | < [M] | Pool activeCount |
```

### 效能壓力測試場景

每個場景都需定義**觸發方式**和**觀察指標**：

1. **最大形狀數** — 容器內塞滿小形狀
2. **快速連續合成** — 連續觸發多次合成（粒子 + 音效同時爆發）
3. **長時間運行** — 30 分鐘持續遊戲，監控記憶體成長
4. **最大 COMBO** — 觸發高 COMBO，驗證視聽回饋不崩潰

## 邊界條件撰寫指南

### 定義模板

```markdown
| 邊界條件 | 觸發方式 | 預期行為 |
|---------|---------|---------|
| [條件] | [如何觸發] | [應該怎麼處理] |
```

### 常見邊界條件

| 類型 | 範例 |
|------|------|
| 物理引擎 | 多對形狀同幀合成、形狀卡牆、高速碰撞穿透 |
| 輸入 | 快速連點、觸控+滑鼠同時、網頁失焦再恢復 |
| 網路 | 斷線提交分數、延遲響應、重複提交 |
| 儲存 | localStorage 不可用、資料損毀、容量滿 |
| 渲染 | WebGPU 不支援降級、高 DPI 螢幕、極端長寬比 |

## 工作流程

1. **制定測試計劃** — 根據 GDD 變更確定測試範圍
2. **環境準備** — 確認平台/瀏覽器覆蓋率
3. **功能驗證** — 逐項執行測試清單
4. **效能測量** — 壓力測試 + 基準比對
5. **邊界測試** — 故意觸發極端情況
6. **GDD 一致性** — 驗證規格數值與程式碼一致
7. **撰寫報告** — 通過/失敗/風險完整記錄
