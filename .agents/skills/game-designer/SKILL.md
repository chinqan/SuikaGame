# 物理落下益智遊戲 — 系統設計師

**職能**：設計核心玩法循環、合成機制、難度曲線、得分經濟，並將設計意圖文件化為可實作的 GDD。

---

## When to Use

- 設計或修改核心玩法循環（投放 → 堆疊 → 合成 → 得分）
- 新增/調整形狀等級、合成規則、COMBO 機制
- 平衡難度（形狀數量、隨機範圍、空間壓力）
- 撰寫 GDD 的遊戲概述、場景設計、流程設計章節
- 分析玩家情感弧線與學習曲線
- 評估新功能是否符合設計支柱

---

## 品質標準

### 規格完整性

- **每個機制都必須定義「輸入 → 處理 → 輸出 → 邊界條件」**
- **數值不能只寫結果，要寫設計意圖** — 例：「COMBO 窗口 1200ms —— 足以讓自然連鎖發生，但不會讓刻意等待也能觸發」
- **公式必須完整，不可模糊帶過** — 例：寫清完整的震動公式，而非「有震動效果」

### 程式碼對應性

- GDD 中的數值**建議標註對應的程式碼常數名**，方便工程師查找
  - 範例：「COMBO 判定窗口 = 1200ms（`COMBO_WINDOW_MS`）」
- 難度系統需精確描述其**配置結構**，讓工程師能直接對應到資料結構
  - 範例：描述「形狀縮減」和「投放等級上限」是兩個獨立的難度軸

### 設計意圖透明

- 每項設計決策都附帶**「為什麼」**，不只是「是什麼」
- 讓後續設計者理解修改某數值會影響什麼體驗

---

## 設計支柱（Design Pillars）

此類遊戲的 3 個不可妥協的核心體驗：

1. **「再來一局」衝動** — 每局結束後玩家立刻想再玩。透過隨機性 + 技巧空間實現
2. **COMBO 爽感** — 連續合成帶來的視聽高潮。合成不只是數字成長，要有感覺
3. **策略深度的錯覺** — 簡單到秒懂，但深到有「如果當時…」的遺憾感

## 核心循環寫作模板

### Moment-to-Moment（0–10 秒）

```
觀察 NEXT → 選擇投放位置 → 點擊投放 → 等待碰撞結果
                                        ↓
                              碰到同級形狀 → 合成！→ 得分 + 視聽回饋
                              未碰到      → 堆疊繼續，觀察下一個
```

### Session Loop（每局 3–10 分鐘）

```
選擇難度 → 遊玩 → 空間壓縮 → Game Over → 分數上傳
                                  ↓
                          超越最高分？→ 成就感 → 再來一局
                          未超越？   → 遺憾感 → 再來一局（想改進）
```

## 合成機制規格撰寫指南

### 規則定義模板

撰寫每個機制時，使用以下結構：

```markdown
## 機制：[名稱]

**目的**：[這個機制存在的理由]
**玩家體驗**：[玩家看到/感受到什麼]
**輸入**：[觸發條件]
**輸出**：[產生什麼結果]
  - 視覺：[粒子/動畫]
  - 聽覺：[音效]
  - 數值：[分數/狀態變化]
**邊界條件**：
  - [情況 A]：[處理方式]
  - [情況 B]：[處理方式]
**調節變數**：[列出可調整數值及其影響]
```

### 合成後物理行為

撰寫合成規格時，必須涵蓋以下面向：

- 新形狀的**初始速度**（方向、大小範圍）— 影響「彈跳感」
- **畫面震動**強度公式 — 應包含等級與連擊的影響因子
- 音效觸發時機 — 與粒子效果的同步關係

> **範例**：「新形狀以隨機方向微彈（vx=±小值, vy=負值），製造合成的『發射感』。震動量隨等級和 COMBO 遞增，讓高等級合成感覺更有力。」

## 難度平衡撰寫指南

### 難度軸定義

撰寫難度系統時，必須明確列出每個的**獨立難度軸**：

```markdown
| 難度軸 | 說明 | 對體驗的影響 |
|--------|------|------------|
| 形狀總數 | 各難度可用多少種形狀 | 越多→空間需求越大 |
| 投放等級上限 | 可隨機投放的最高等級 | 越高→隨機性越大 |
| 容器尺寸 | 遊戲區域大小 | 通常固定，但可作為難度軸 |
```

> **品質標準**：每個難度軸必須是獨立的可調參數，讓設計者能單獨調整而不影響其他軸。

### 平衡原則

- 難度差異應來自**內容量變化**，不來自物理參數改變
- 所有難度共用同一物理引擎設定 — 保持「手感一致」
- 分數經濟不因難度改變 — 排行榜按難度分組即可

## 玩家心理撰寫指南

### Pacing Chart 模板

```
時間      | 活動          | 張力    | 情緒
----------|-------------|--------|------------------
0:00-0:30 | 探索/學習     | Low    | 好奇
0:30-2:00 | 堆疊成長     | Medium | 信心建立
2:00-4:00 | 空間壓縮     | High   | 策略思考+緊張
4:00-6:00 | 大合成爽感   | Release| 成就感爆發
6:00-8:00 | 接近頂端     | Peak   | 焦慮/風險決策
8:00+     | Game Over   | Max    | 挫敗→「再來一局」
```

### 學習曲線設計原則

1. **0–15秒**：核心操作自明（不需教學）
2. **1–3局**：自然發現合成機制
3. **3–5局**：理解位置策略的重要性
4. **5+局**：開始利用預覽做規劃

## 數值設計 Checklist

- [ ] 每個等級的半徑增幅是否非線性遞增？
- [ ] 得分曲線是否讓高等級合成「值得追求」？
- [ ] 最大形狀是否佔容器面積 >10%？（空間壓力保證）
- [ ] COMBO 窗口時間是否讓「自然連鎖」可觸發？
- [ ] 難度差異是否只來自內容量，不來自物理感？
- [ ] 理論最高分是否在合理範圍？

---

## 工作流程

1. **定義設計支柱** — 確認遊戲的核心體驗承諾
2. **撰寫核心循環** — 從玩家視角描述 moment-to-moment
3. **建立數值表** — 半徑/分數/難度的完整數據，附設計意圖
4. **情感弧線** — 畫出 Pacing Chart
5. **邊界條件** — 定義每個機制的極端情況
6. **Playtest 驗證** — 與設計意圖對比實際體驗
