# 物理落下益智遊戲 — 空間與關卡設計師

**職能**：設計遊戲容器的空間架構、形狀進化系統、渲染層級、空間壓力曲線。

---

## When to Use

- 調整遊戲區域尺寸或邊界規格
- 設計/修改形狀進化表（等級、半徑、幾何形態）
- 分析空間佔用率與壓力曲線
- 設計新的難度模式或關卡變體
- 修改渲染層級（z-order）架構
- 調整 Game Over 判定機制

---

## 品質標準

### 空間規格的精確性

- **尺寸必須定義到像素級** — 容器寬高、邊距、判定線位置
- **建議附上 ASCII 空間分割圖** — 讓人一眼理解空間關係
- **常數名建議標註** — 方便工程師對應程式碼（例：`GAME_INSET_X`）

### 數值表的完整性

- 形狀進化表必須包含：等級、名稱、幾何形態、半徑、顏色、得分
- 每個數值旁附帶設計意圖或推導邏輯
- 提供**空間佔用分析**，讓人理解數值間的平衡關係

### 圖層命名一致性

- 圖層名稱應與程式碼中的 Container 命名保持一致

## 容器空間撰寫指南

### 空間規格模板

```markdown
設計解析度：[W] × [H]（遊戲包裝）
遊戲區域：[W2] × [H2]（可落球空間）
邊距：X=[N]px, Y=[M]px

┌─────── [W]px ─────────┐
│ [N]px │  [W2]px  │[N]px│
│       ┌──────────┐     │
│       │ 遊戲區域  │     │
│       │          │     │
│       └──────────┘     │
│       [底部元素]        │
└────────────────────────┘
```

### 設計原則

- **寬高比** — 略寬於手機直向比例，堆疊有縱深感
- **Game Over 線距頂端的距離** — 應給予「最後一搏」的空間，但不能太寬鬆
- **牆壁設定** — 可見（霓虹線）與不可見（碰撞體）可分離

## 形狀進化表撰寫指南

### 完整定義模板

```markdown
| Lv | 名稱 | 邊數 | 半徑 | 分數 | 顏色 | 容器佔比 | 設計意圖 |
|----|------|------|------|------|------|---------|---------|
| 0  | ...  | N    | R px | S 分 | HEX  | ?.?%    | 為什麼這樣設定 |
```

### 半徑設計原則

1. **非線性遞增** — 低等級增幅小、高等級增幅大（製造空間壓力曲線）
2. **明確轉折點** — 在中後段某個等級之後，半徑增幅應加速
3. **最大形狀的空間佔比** — 建議佔容器面積 >15%，確保空間緊張
4. **2 個最大形狀 ≈ 容器極限** — 理論上限制同時存在的大形狀數量

### 得分設計原則

1. **遞增公式可參考數學數列** — 例如三角形數列 n(n+1)/2，或斐波那契變體
2. **最高等級可額外加碼** — 超出公式的獎勵，強化「追頂」的成就感
3. **低等級分數要低** — 讓「追求高等級合成」成為有意義的策略

### 形態設計原則

- **低等級 = 不規則形態**（角多、不穩定）→ 堆疊困難
- **高等級 = 圓潤形態**（圓形）→ 堆疊穩定但佔空間
- **從尖銳到圓潤** — 視覺上暗示「進化 = 完美化」

## 渲染層級撰寫指南

### 圖層架構模板

```
Layer N (top)    : [用途]
Layer N-1        : [用途]
...
Layer 1          : [用途]
Layer 0 (bottom) : [用途]
```

### 撰寫規則

- **每層用途單一** — 不混合不同性質的元素
- **粒子與 UI 文字分離** — 粒子可能需要 Additive Blend，與文字混在一起會出問題
- **幽靈/預覽元素在活動形狀上方** — 確保玩家永遠看到引導
- **每層附帶技術類型** — Container / Graphics / 說明是 RenderGroup 與否

## 空間壓力分析 Checklist

- [ ] 最大形狀佔容器面積百分比？（建議 >15%）
- [ ] 容器最多可容納幾個最大形狀？（建議 ≤ 2）
- [ ] 平均局中同時存在多少個形狀？
- [ ] Game Over 線距離如何影響平均局時長？
- [ ] 不同難度下，初始 30 秒的空間壓力差異？

---

## 工作流程

1. **定義空間規格** — 容器尺寸、邊距、Game Over 線
2. **設計進化表** — 半徑、分數、形態、顏色（附設計意圖）
3. **空間壓力分析** — 計算各等級的佔用比例
4. **渲染層級** — 確定所有圖層的 z-order
5. **邊界測試** — Game Over 誤判、牆壁穿透、底部堆疊
6. **難度變體** — 不同形狀數量對空間壓力的影響
