---

## Step 10.2 — 跨章節一致性驗證

逐項檢查以下一致性：

### 數值一致性
- [ ] 形狀定義表：02 的表 = 03 的 config 引用 = 08 的粒子等級引用
- [ ] 物理參數：03 的表 = technical-artist Skill 的參考值
- [ ] 設計解析度：02 = 03 = 05 中引用的值
- [ ] 難度配置：02 的表 = 01 中的描述 = 09 的測試項

### 命名一致性
- [ ] 圖層名稱：02 的圖層表 = 03 的 Container 名稱
- [ ] 常數名稱：跨章節引用的常數名一致
- [ ] 形狀名稱：02 的進化表 = 07 音效對應 = 08 粒子對應

### 邏輯一致性
- [ ] 06 遊戲流程中提到的所有系統都在 03 架構圖中
- [ ] 08 效能預算 = 09 測試指標
- [ ] 04 的視覺效果在 08 有技術規格

---

## Step 10.3 — 最終驗收

GDD 完成後必須滿足 5 個標準：

1. ✅ **架構師可理解** — 任何工程師讀完能獨立實作
2. ✅ **設計意圖透明** — 每個「是什麼」都附帶「為什麼」
3. ✅ **數值精確** — 公式完整、建議標註常數名
4. ✅ **跨章節一致** — 同一數值在不同章節無矛盾
5. ✅ **可測試** — 每項規格在 09 有對應的驗收標準
