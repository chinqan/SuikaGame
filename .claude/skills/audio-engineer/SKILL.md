# 物理落下益智遊戲 — 程式合成音效工程師

**職能**：設計 Web Audio API 程式合成音效系統，定義 Sonic Identity、狀態回饋、Voice Budget。

---

## When to Use

- 設計新的合成音效或互動音效
- 定義遊戲的 Sonic Identity（聲音識別）
- 新增/調整音效包（Sound Pack）
- 優化行動裝置音效效能
- 定義音效隨遊戲狀態變化的行為

---

## 品質標準

### 音效規格的可還原性

- **每個音效必須完整定義波形圖層** — 振盪器類型、頻率公式、包絡線、效果器
  - 範例：定義「噪音爆炸層」時，需寫明 BufferSource + LPF 的截頻/衰減
- **頻率公式中的等級（Level）影響必須明確** — 高等級合成應聽起來不同
- **所有時間參數必須以秒或毫秒表示**

### 音效包的結構一致性

- 每個音效包（Sound Pack）必須包含相同的圖層結構，只有參數不同
- 切換音效包不應影響遊戲邏輯

### Voice Budget 的嚴格控制

- 定義最大同時發聲數，防止行動裝置崩潰
- 定義「不可省略」和「可在效能壓力下跳過」的音效層

## 音效架構撰寫指南

### 合成音效圖層模板

每個音效由多個波形圖層疊加：

```markdown
## 音效：[名稱]

| 圖層 | 波形類型 | 頻率 | 持續時間 | 用途 |
|------|---------|------|---------|------|
| 基底 | [type] | [freq 公式] | [duration] | [聽覺角色] |
| 中頻 | [type] | [freq 公式] | [duration] | [聽覺角色] |
| 高頻 | [type] | [freq 公式] | [duration] | [聽覺角色] |
| 尾韻 | [type] | [freq 公式] | [duration] | [聽覺角色] |
```

### 頻率設計原則

- **等級影響音高** — 高等級合成應有更高、更飽滿的音效
  - 範例公式：`baseFreq + level × step`
- **COMBO 影響音量或諧波** — 連擊帶來漸強的聽覺獎勵
- **音高不可超出人耳舒適範圍** — 避免 >8000Hz 的刺耳高音

## 音效包（Sound Pack）撰寫指南

### 定義模板

```markdown
| # | ID | 顯示名稱 | 聽覺特色 |
|---|-----|---------|---------|
| 1 | standard | 📦 標準 | [特色描述] |
| 2 | crystal | 💎 水晶 | [特色描述] |
```

### 設計原則

- 每個音效包**保持相同的圖層結構**，只改變波形/頻率/濾波器參數
- 提供**預覽功能** — 玩家在設定中可試聽每個等級的音效
- 音效包的差異應足夠明顯 — 玩家閉眼也能分辨

## Voice Budget 撰寫指南

### 預算模板

```markdown
| 平台 | 最大同時發聲數 | 壓縮策略 |
|------|-------------|---------|
| 桌機 | [N] | 完整品質 |
| 行動裝置 | [M] | [簡化方式] |
```

### 優先級定義

將音效圖層分為必要和可選：

| 類型 | 效能壓力下的策略 |
|------|----------------|
| **必要層** | 永遠播放 — 例：基底爆炸音 |
| **增強層** | 可省略 — 例：泛音裝飾、尾韻 |
| **環境層** | 可降低品質 — 例：降低採樣率 |

## 工作流程

1. **Sonic Identity** — 定義核心聽覺感受
2. **基礎音效** — 設計合成觸發音效（主要遊玩回饋）
3. **音效包** — 設計多套風格變體
4. **狀態回饋** — 定義音效隨遊戲狀態的變化
5. **Voice Budget** — 設定效能限制與優先級
6. **試聽驗證** — 在目標裝置上聽過，確認不刺耳
